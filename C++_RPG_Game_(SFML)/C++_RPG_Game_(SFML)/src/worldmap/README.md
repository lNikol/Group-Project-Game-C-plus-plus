# Map & Asset Communication System

This directory contains the core logic for translating Tiled Map Editor outputs (`.tmj`) and automated asset manifests into a playable game world.

## 1. Data Flow Architecture

The system follows a strict "Data-Driven" pipeline:

1. **Python Script**: Processes raw images -> Generates `atlas.png` and `manifest.json`.
2. **Tiled Editor**: Uses the processed images to create maps -> Exports `map.tmj`.
3. **C++ AssetManager**: Loads `manifest.json` to map names (e.g., "oak_tree") to UV coordinates.
4. **C++ WorldMap**: Parses `map.tmj`, matching GIDs and Object Names to definitions in `AssetManager`.

---

## 2. Layer Logic

The `WorldMap::loadMap` function processes layers in a specific order to ensure correct rendering and collision:

| Layer Name          | Type          | Purpose           | Logic                                                                         |
| :------------------ | :------------ | :---------------- | :---------------------------------------------------------------------------- |
| **Ground**          | `tilelayer`   | Base terrain      | Uses `processTileLayer`. All tiles here are non-blocking by default.          |
| **Decorations**     | `objectgroup` | Visual flavor     | Small plants, flowers, debris. Usually non-blocking. Rendered above Ground.   |
| **InteractObjects** | `objectgroup` | Dynamic items     | Chests, barrels, or items that can be destroyed/opened.                       |
| **Obstacles**       | `objectgroup` | Static structures | Uses `processObjectLayer`. Objects with `gid` (trees, rocks) are placed here. |
| **SpawnPoints**     | `objectgroup` | Logic points      | Contains `PlayerSpawn` and `NPC` points (name-based).                         |

---

## 3. Object Processing (The `gid` Rule)

In `processObjectLayer`, we distinguish between two types of data:

### A. Tile Objects (`gid != 0`)

When you drag an image from a Tileset in Tiled, it receives a **Global ID (GID)**.

- **Visuals**: Position is adjusted by `y - height` because Tiled anchors Tile Objects from the bottom-left.
- **Matching**: We subtract 1 from the GID (`gid - 1`) to match the index in our `AssetManager`.

### B. Logic Shapes

Created using Tiled's shape tools (Point, Rectangle) (click 'I').

- **PlayerSpawn**: A point object named exactly `PlayerSpawn`. Its `x, y` are used directly as the player's starting coordinates.
- **NPCs**: Points named after their role (e.g., `Gatekeeper`). Also parses npc pos (x,y).

---

## 4. Hitboxes & Collision

Collision is not handled by Tiled's collision editor to keep the workflow fast. Instead:

1. **Templates**: `templates.json` defines properties for prefixes (e.g., any object starting with "tree" blocks movement).
2. **Precise Hitbox**: The engine reads `hb_w`, `hb_h`, `off_x`, and `off_y` from `manifest.json` (generated by the Python script).
3. **Coordinate Correction**:
   - `WorldX = obj.x - offsetX`
   - `WorldY = (obj.y - obj.height) - offsetY`

---

## 5. Adding New Content

To add a new NPC or Interactable:

1. Open Tiled, select the **Insert Point** tool.
2. Place it on the `SpawnPoints` layer.
3. Name it (e.g., `NPC_Merchant`).
4. In C++, ensure `processObjectLayer` handles the new name or class.
